Exact text protocol v1

What this run measures

Each scenario starts a fresh visitor conversation against the avatar’s current English text pipeline. Follow-ups retain the same history and the normal visitor limit of five questions. Test exchanges are isolated from visitor history and analytics.

Response fidelity
Every response must match its reference answer exactly. Only leading and trailing whitespace is ignored. Internet fallback fails the reference-only check.
Critical findings
A mismatch in an urgent or emergency reference is conservatively flagged as critical for human review. This label does not establish an independently validated clinical-routing failure.
Conversation pass
Every checked turn must pass. An error, cancellation, unexecuted turn, or timeout cannot count as a pass.
Configuration evidence
Runs preserve the answer key, source knowledge, avatar configuration, protocol version, responses, and citations. Changes detected during execution cause an error. Historical runs are marked for retesting when their configuration changes.
Approval and review
Draft answers block readiness. Record existing approval evidence with the approver’s name and date. Review decisions are appended; they never replace the automated result.
Scope
Text channel only. Clinical correctness, independent urgency assessment, audio recognition, speech delivery, translations, and regulatory approval are not established by these checks. Model-provider behavior can vary between runs.
Operational limits
Up to 100 scenarios, five visitor turns each, one active run per avatar card, and ten runs per initiating user per day. Each run makes live model calls and consumes provider usage. Never include patient records or identifying details in test fixtures.

Your first focused test

How to test this avatar

QA asks {{ data()?.target?.avatarName }} your test questions and records the actual answers. Start with a few facts and boundaries that matter for this avatar.

  1. Download the example. Edit the questions, expected answers, and sources. For your first suite, try 3–10 scenarios. The example answers are drafts based on a script, not observed successful responses.
  2. Upload and preview. Choose a JSON file or paste its contents. Invalid entries and duplicate IDs are flagged before anything is added.
  3. Review and save the library. Use Edit to inspect each answer. Keep unreviewed answers as drafts; record an approver and date only when approval actually exists.
  4. Run tests. Once saved, select Run tests and confirm the questions are synthetic. Each scenario starts a fresh English text conversation; follow-ups keep that scenario’s history. Runs consume live AI-provider usage.
  5. Read the actual responses. Open Test conversations to compare expected and actual answers, inspect citations, and record a review. Fix the avatar’s script or knowledge where needed, then rerun.
Exact wording, not a judgment of meaning

The complete answer must match the reference, including punctuation and any Sources line. Only outer whitespace is ignored. A correct paraphrase can fail, and internet fallback fails the reference-only check. Read the actual response before deciding what needs fixing.

What goes in the JSON file?

Use an array of test entries. The example and blank template have the right structure.

id
A unique reference such as GIST-001. Use letters, numbers, hyphens, or underscores.
question
The visitor’s question, up to 1,000 characters.
expectedAnswer
The complete reference response, up to 6,000 characters.
category
education, boundary, urgent, or emergency. Mismatches in urgent or emergency are marked critical.
source
The document, script section, or version supporting the answer.
approval
draft by default. approved requires approvedBy and a valid approvedOn date in YYYY-MM-DD format.
followUps
An optional array of up to four additional question and expectedAnswer pairs.

These checks cover English text only. They do not test audio or translations, train the avatar, or automatically prevent a live response. Drafts and failed tests block review readiness; a passing run still needs human review. Use synthetic questions without private or identifying information.
